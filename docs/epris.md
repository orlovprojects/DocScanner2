# EPRIS preparation

Updated 2026-09-08. The module prepares purchase lines and invoice copies for a Lithuanian applicant. It does not submit an application or establish entitlement to a refund.

## Workflow and selection

Select one applicant and its observed variants using the same key precedence as OSS: company code, VAT number, name. All queries are scoped to the signed-in user. A purchase requires a selected buyer and an unselected seller. Sales, unmatched documents and matches on both sides are counted separately. Digitized documents are the source; issued sales invoices are excluded.

Refund country defaults to the supplier VAT registration country, with EL mapped to GR, then falls back to the supplier address country. Review can override it. Lithuanian VAT, countries outside the EU, missing dates and zero VAT are excluded from country summaries. Credit notes remain visible for review and require separate correction handling. Missing exchange rates remain unknown and block export.

The standard workflow only asks for a category and, where required, a subcategory. Refund country comes from the invoice; the default deduction is 100% of its VAT. Country, deduction percentage, amount and simplified-invoice settings remain editable under “Papildomai”. Category-only API updates use the same defaults. Values matching the automatic country and amount are not stored as fixed overrides, so they follow later invoice edits. Readiness is recalculated from current invoice data and category validity; there is no confirmation checkbox or confirmation fingerprint. Exact duplicate selections and invalid export data are still rejected on the server.

The page automatically selects the country, period and ready invoices after applicant selection. Changing filters clears stale results. Saving a category selects that invoice when ready. Direction diagnostics and long help text are not displayed in the normal workflow; historical exports are available in collapsed additional filters. Export totals show the selected deductible amount.

The compact table has separate invoice date/number columns, taxable base and VAT rate ("Keli skirtingi" for the document's mixed-rate flag). The request total is labelled and displays the selected currency and an estimated EUR equivalent. Category tooltips contain code/name labels only, without hierarchy paths or validation messages. The preview includes supplier company/VAT IDs, address/country and original invoice amounts. A supplier VAT prefix/address-country mismatch has its own visible warning and does not itself block a legitimate foreign VAT registration. Missing company ID never automatically marks a document as a simplified invoice.

Export blockers are visible even before attempting export: period errors use a persistent error Alert and insufficient selected VAT uses a warning Alert with the required amount, selected amount and shortfall (including zero selection). Every unready invoice has a separate red error icon with its reasons in a tooltip; clicking it opens the preview, where those reasons and save errors appear in an Alert at the top. Custom period choices explain full calendar months, the 400 EUR threshold, and the 50 EUR full-year/year-remainder exception. The mixed-activity section and coefficient input have been removed from the UI; existing saved coefficients are retained. The preview shows an informational Alert when the country's category options require subcategories, and marks the relevant subcategory field as required with an explanation (preserving the category 10 description alternative).

A missed submission deadline is a non-blocking warning titled "Prašymo pateikimo terminas praleistas", displaying the actual September 30 deadline year. `deadline_passed` is separate from blocking `period_errors`. Both CSV and attachment downloads remain available after the deadline if all other validations pass; downloading does not submit anything to EPRIS or extend the legal deadline. The 400/50 EUR application minimum uses selected refundable VAT, while the separate 1000/250 EUR invoice-copy thresholds use taxable value.

Editable amounts use comma decimals. `deduction_percent` is the requested share of invoice VAT and is linked to `deductible_vat` in both directions. Exact monetary amounts are retained when rounding the displayed percentage would lose cents. `prorata_rate` is the separate activity deduction coefficient, defaults to 100, and still caps the claim when set lower. It must be an integer; CSV leaves VI_PRORATARATE empty at 100 and writes an integer otherwise. A fractional requested share is not exported as an activity coefficient. Existing saved prorata settings are preserved. No database migration is needed for these JSON keys.

Document amounts are not automatically converted to refund-country currency. LB/reference exchange rates can support estimates but do not by themselves establish the country's correct taxable/VAT amount or applicable conversion date. The currency mismatch continues to block export pending valid amounts in the refund currency.

## Official requirements and limits

The [VMI EPRIS manual](https://www.vmi.lt/epris/Content/Help/R38_ITIS_EU_EPRIS_IP.htm), sections 4.2.1.3.5 and 4.2.1.2.4, documents the purchase CSV layout and attachments. CSV contains PurchaseInformation and PurchaseInformation_GoodsDescription, semicolon-separated, with linked parent IDs and purchase sequence numbers starting at 500001. Invoice files are separate attachments. PDF, JPEG, TIFF and ZIP are accepted; ZIP contents must be permitted documents without folders. Names must be unique. The application and all attachments together must fit within 5 MB. The download guard limits the archive but cannot know the final portal application's size; the user must leave room for it. CSV is a purchase-line import, so applicant identity, activity, contact, bank details and declarations still need completing in the portal.

[Directive 2008/9/EC](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32008L0009), Articles 3–6, 8–10 and 15–20, governs eligibility, invoice information and periods. Local deduction restrictions and business use require review; category selection alone proves neither. Countries may require invoice copies from a taxable value of EUR 1,000, or EUR 250 for fuel, and request additional evidence below those levels. The normal period is 3–12 calendar months in one year; a shorter year remainder is allowed. Minimum claims are EUR 400, or EUR 50 for a calendar year or expressly selected year remainder. Submission is due by September 30 of the following year. Currency equivalents shown here are estimates from the existing exchange-rate table; country-specific portal checks remain authoritative.

The repository's subcode country matrix cites a 2011 source. It is retained as a historical aid, not represented as a current eligibility matrix. Verify current category, language and deduction requirements in [the Commission's TIC service](https://ec.europa.eu/taxation_customs/tic/) or EPRIS. Unsupported country-specific exceptions and import/customs records must be prepared separately.

## Deployment and verification

Apply migration `0171_scanneddocument_epris_details` before serving the updated API. Existing category data and manual amount overrides are retained; blank amounts use the automatic defaults. Historical `epris_submitted_at` values are left untouched because previous exports set them without evidence of submission. Additional filters can include those rows. New downloads never set that field.

`python manage.py test docscanner_app.test_epris` runs isolated rule and API regression tests using mocked document/rate sources, with no production database or network. UI verification uses a temporary local fixture with fictional companies and invoices. A successful build or CSV schema test does not establish that a particular country's live EPRIS validation will accept the application; no live submission was performed.

The attachment exporter preserves PDF/JPEG/TIFF originals and converts single-frame PNG/WebP/BMP copies to PDF with a white background. Unsupported, unreadable, oversized or multi-frame conversion inputs produce an explicit error. Original stored files are never modified.

Attachment names use the CSV sequence followed by the invoice series/number, for example `500001_A42.pdf`, instead of the database ID. The reference is normalized to ASCII, unsafe characters become underscores, and its length is capped; an empty sanitized reference falls back to `saskaita`. The sequence preserves unique archive names even when invoice numbers collide. Invoice numbers in the table are selectable plain text for copying; the category and error controls still open the preview. EPRIS notifications omit terminal periods, and the subcategory requirement uses an orange warning Alert.
